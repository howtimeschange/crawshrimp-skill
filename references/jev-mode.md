# JEV execution mode

Use this opt-in mode after the normal 9222 observation and API-first exploration.
First reuse a verified page-owned API, phase script, or distilled workflow when one
already solves the task. Exact calculations, extraction, pagination of a known API,
and workflow replay belong in code and need no model calls. JEV helps when the next
safe UI operation or its observed target still needs semantic selection.

## Run one bounded goal

```bash
python3 scripts/jev_operator.py \
  --tab-id YOUR_OBSERVED_TAB_ID \
  --url-prefix https://books.toscrape.com/ \
  --goal 'Read pages one through three; stop on page three.' \
  --scope-selector '.pager' \
  --dom-fallback-reason 'This public static site exposes HTML links, no page-owned data API.' \
  --verify-expression "location.pathname.endsWith('/page-3.html') && document.querySelectorAll('article.product_pod').length === 20" \
  --progress-expression "JSON.stringify([...document.querySelectorAll('article.product_pod h3 a')].map(a=>a.href))" \
  --journal artifacts/books-jev.jsonl
```

The calling agent supplies the scope, exact target envelope, proof, and any optional
extraction expression from observed page evidence. These are trusted local code,
never generated by JEV. `--observation-expression` can return public records atomically
with each snapshot. Returned observations may repeat while loading: deduplicate by
stable record IDs and independently check the requested page and record counts.

Credentials come from `TYPESAFE_API_KEY` in the process environment or the existing
`~/.config/jev-jarvis/env` (override with `--config-file`). Keys are not printed or
written to journals. Host-only, `/v1`, and complete TypeSafe-compatible action URLs
are supported. No global configuration or installed plugin cache is changed.

## What runs faster

- One JEV request contains operation and compatible-target questions in parallel.
  Only the target head selected by the operation is consumed.
- A local goal loop replaces a host-agent/tool round trip for every click.
- One WebSocket stays attached to the exact tab for the whole goal. One atomic
  browser evaluation reads controls, optional data, progress, and completion proof.
- One HTTPS connection is reused for decisions. Screenshots are outside the default
  loop. Timing separates model time, browser protocol calls, recovery, and total time.
- Exact field values come from `--values-json`, keyed by observed field name or ref.
  Missing text returns to the calling agent instead of making another model invent it.

## Correctness and recovery

Dynamic references point to actual observed nodes. Before input, execution checks
the document, URL, scope text, field values, nearby context, connected nodes,
disabled state, and current hit testing. It resolves geometry after scrolling.
Stale decisions are discarded and re-observed within a bounded model-call budget.
An action is consumed before input. If its outcome becomes unknown, return
`BROWSER_ACTION_UNCERTAIN` and inspect the original outcome; never replay it.

For a page that says `Page Unavailable` or a comparable temporary error, reload
once and read back. If that lands on the same site's home page, restore the expected
target once and verify again. A persistent error hands control back. Login and
captcha require human verification and never enter a reload loop. Recovery applies
to a read/navigation goal, not to an unknown save, payment, submission, or send.

Readiness is a predicate, not a fixed delay. In particular, a pagination button can
update before its cached rows change. Supply `--progress-expression` over stable
row IDs or the relevant result data so the executor waits for new content. Timeout
returns a specific no-progress result and does not click again blindly.

Both operation and selected-target probability distributions are validated. Low
confidence hands off by default. `--fallback-on-uncertainty` optionally asks the
configured OpenAI-compatible model to choose from the same offered IDs when JEV
confidence is low. Both providers' time and the fallback count are recorded. The
fallback uses the same live-reference guards and outcome proof; it cannot produce
code, selectors, unobserved targets, or missing text. Its numeric format adapters
are explicitly labeled as uncalibrated. Confidence is not authorization or evidence of success.
`DONE` must pass the caller's independent code proof. Dangerous controls, sensitive
fields, external-origin links, file inputs, and popup-tab links are excluded. The
scope should contain only the navigation/filter controls needed by this goal.
Uploads and externally visible writes remain in the normal authorized API-first
operator; JEV mode does not add permission to save, send, publish, delete, or pay.

## Sources and measurement

Inspired by [browser-use/jev-ultrafast](https://github.com/browser-use/jev-ultrafast),
especially its dynamic operation/target heads, atomic snapshots, node freshness,
and independent outcome checks. Also reviewed
[jev-ultrafast-mcp](https://github.com/jiawei686/jev-ultrafast-mcp) for its whole-goal
loop, protocol reuse, stalled-target handling, and zero-model workflow replay.
The implementation uses Crawshrimp's existing CDP entry and dependencies.

Keep source tests, real browser guard checks, model decisions, extracted data,
downloaded artifacts, and final application state as separate evidence. Report
initial exploration, manual authentication, cold connections, and recovery outside
or inside the timed interval explicitly. Compare successful identical tasks; a
blocked site does not establish a model speed difference. A single public sandbox
run is a local experiment, not a production reliability or general speed claim.
